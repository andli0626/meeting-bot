## 一、为什么不能只从代码里删掉名字

这是本次变更最关键的一点，直接决定了方案。

配置对话框会把参会人员名单记到浏览器本地（Tampermonkey 的 GM 存储，键名 `oa_weekly_user_config`）。脚本打开对话框时的取值链是：

```javascript
// code/oa-weekly-meeting.user.js:345
const participantText = dropDeparted(
  saved.participantNames && saved.participantNames.length
    ? saved.participantNames      // ← 优先：本地记住的旧名单
    : CONFIG.participants,        // ← 兜底：代码里的默认名单
  "参会人员",
).join("、");
```

只要用户点过一次「确认执行」，`saved.participantNames` 就有值了，此后**每次打开对话框带出的都是那份旧名单**，`CONFIG.participants` 根本不会被读到。

因此，只做「从 `CONFIG.participants` 里删掉左惠」这一件事，会出现典型的假成功：

| 表面现象               | 实际情况                                       |
| ---------------------- | ---------------------------------------------- |
| 代码 diff 干净         | 确实改了                                       |
| 语法校验通过           | 确实通过                                       |
| 会议里左惠**还在**     | 本地旧名单盖掉了代码里的新名单                 |

**结论：人员离职时，只改代码里的默认名单是不够的。**

---

## 二、解决方案：反向登记 + 双点过滤

不去修补「哪份名单优先」这个历史设计（改动面大、影响其它已记住的配置），而是**新增一份离职人员名单，从两个来源同时剔除**。

```javascript
// code/oa-weekly-meeting.user.js:106
departedParticipants: ["左惠"],
```

这样带来两个直接好处：

1. **历史数据自愈** —— 用户打开对话框时旧名单里的左惠已被剔除，点一次「确认执行」就会把干净名单写回本地，不需要任何手工清理。
2. **后续维护成本极低** —— 以后再有人离职，只往这一行加个名字即可，不用管本地存了哪些历史名单。

### 过滤函数

新增 `dropDeparted()`（`code/oa-weekly-meeting.user.js:283`）：

```javascript
function dropDeparted(names, source) {
  const departed = (CONFIG.departedParticipants || []).map((n) => String(n).trim());
  if (!departed.length || !Array.isArray(names)) return names;
  const removed = [];
  const kept = names.filter((name) => {
    const n = String(name).trim();
    if (departed.includes(n)) {
      removed.push(n);
      return false;
    }
    return true;
  });
  if (removed.length) {
    Logger.info(`${source}名单中已剔除离职人员: ${removed.join("、")}`);
  }
  return kept;
}
```

设计要点：

- **两个来源统一过滤** —— 函数不关心名单来自代码还是来自本地，两条路径都走它。
- **带 `trim()` 比较** —— 对话框里手填的 `" 左惠 "`（带空格）也能正确剔除。
- **过滤成功必打日志** —— 这是本次特意加的**可观察信号**，用于对抗上文那种「假成功」：`参会人员名单中已剔除离职人员: 左惠`。
- **名单里没有离职人员时不报错** —— 返回原数组，行为与改动前完全一致。

### 两个调用点

| 时机           | 位置                    | 作用                                                   |
| -------------- | ----------------------- | ------------------------------------------------------ |
| 打开对话框时   | `oa-weekly-meeting.user.js:345` | 剔除本地旧名单里的离职人员，用户看到的输入框就是干净的 |
| 点「确认执行」 | `oa-weekly-meeting.user.js:480` | 剔除手填内容里的离职人员，并把干净结果**写回本地**，完成自愈 |

## 六、使用者操作步骤

1. **更新脚本**：把 `code/oa-weekly-meeting.user.js` 内容整体复制到 Tampermonkey 的脚本编辑器，保存。
2. **确认人员栏**：打开「周例会配置确认」对话框，参会人员栏应显示 8 人且无左惠。
3. **一次确认即自愈**：点一次「确认执行」，本地记住的旧名单会被覆盖成干净名单。若想立刻清空，也可菜单「重置本地配置（恢复内置默认值）」。
4. **看日志确认**：菜单「查看执行日志」，应能看到 `参会人员名单中已剔除离职人员: 左惠`。**看不到这一行说明旧脚本没更新成功**。

## 七、后续人员变动速查

### 人员离职（推荐做法）

在 `CONFIG` 里加一行即可，代码名单和本地旧名单都会被自动剔除：

```javascript
departedParticipants: ["左惠", "张三"],   // 名字写法与 OA 通讯录完全一致
```

同时建议顺手把该人员从 `participants` 和 `participantGuids` 中删除，避免名单里留着无用项。

### 人员入职

⚠️ **注意：只加 `participants` 可能不生效。** 同样因为本地旧名单优先级更高，新人会被挡在门外（症状与离职相反，是「新人进不去会议」，更不容易被发现）。

当前 v1.6.1 的两个可选做法：

- **做法 A（推荐，最省事）**：在配置对话框的「参会人员」栏里把新人加上，点「确认执行」即可，脚本会记住。
- **做法 B**：改代码的 `participants` + `participantGuids`，然后在浏览器控制台清掉本地存储，或菜单「重置本地配置」。
