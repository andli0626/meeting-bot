# 新点OA周例会自动化 - 人工测试验证指南

## 一、测试前准备

### 1.1 环境要求

| 项目 | 要求 | 检查方法 |
|------|------|---------|
| 操作系统 | Windows 10/11 | `winver` 命令 |
| 浏览器 | Chrome 120+ 或 Edge 120+ | 地址栏输入 `chrome://version` |
| Tampermonkey | v5.0+ | 点击工具栏图标，确认版本号 |
| 网络 | 内网可访问 oa.epoint.com.cn | 浏览器访问测试 |
| OA 账号 | 有效账号且已登录 | 手动访问 OA 确认登录态 |

### 1.2 文件清单

确认以下文件已准备好：

| 文件 | 用途 | 阶段 |
|------|------|------|
| `oa-weekly-meeting-validator.user.js` | 技术验证脚本（推荐先安装） | 阶段一：验证页面结构和选择器 |
| `oa-weekly-meeting.user.js` | 完整功能油猴脚本 | 阶段二：确认选择器正确后安装 |
| `OA周例会自动化-实现方案.md` | 技术方案文档 | 参考 |
| `OA周例会自动化-测试指南.md` | 详细测试用例文档 | 参考 |

## 二、安装步骤

### 2.1 安装 Tampermonkey

1. 打开 Chrome 浏览器
2. 访问 [Tampermonkey 官方页面](https://chromewebstore.google.com/detail/tampermonkey/dhdgffkkebhmkfjojejmpbldmpobfkfo)
3. 点击"添加至 Chrome"
4. 确认安装成功（工具栏出现 Tampermonkey 图标）

### 2.2 安装自动化脚本

1. 点击浏览器工具栏的 **Tampermonkey 图标**
2. 选择 **"添加新脚本"**
3. 用文本编辑器打开 `oa-weekly-meeting.user.js`
4. **复制全部内容**（Ctrl+A → Ctrl+C）
5. 粘贴到 Tampermonkey 编辑器中（Ctrl+V）
6. 按 **Ctrl+S** 保存
7. 确认脚本已启用（Tampermonkey 图标显示数字"1"）

### 2.3 验证安装

1. 访问 `https://oa.epoint.com.cn/epointoa9/frame/fui/pages/themes/aide/aide?pageId=aide`
2. 确认页面标题为"新点网上协同办公平台"
3. 点击 Tampermonkey 图标，确认"新点OA周例会自动化"显示为"已启用"
4. 按 F12 打开开发者工具，切换到 Console 面板
5. 确认看到 `[OA-Weekly] 页面已加载完成，开始执行` 日志

## 三、测试流程

### 阶段一：技术验证（推荐先执行）

安装 `oa-weekly-meeting-validator.user.js`。该脚本默认不自动执行，需通过 Tampermonkey 菜单手动触发"立即执行技术验证"。

此脚本会自动完成以下验证：
1. 检测登录状态
2. 定位".modicon-1"图标并点击
3. 验证会议看板是否打开
4. 输出页面结构信息（按钮、图标、iframe 列表）

**通过标准**：前三步全部成功，确认核心选择器有效后再进入阶段二。

## 五、问题排查

### 5.1 常见问题

#### 问题 1：脚本不执行

**可能原因**：
- Tampermonkey 未启用脚本
- `@match` 不匹配当前 URL
- 页面 CSP 阻止注入

**排查步骤**：
1. 点击 Tampermonkey 图标，确认脚本开关为绿色
2. 确认 URL 为 `https://oa.epoint.com.cn/epointoa9/frame/fui/pages/themes/aide/aide*`
3. Console 查看是否有 CSP 相关错误

**解决方案**：
- 启用脚本
- 确保访问的是正确的 URL
- 如果 CSP 阻止，考虑使用 Chrome 插件方案

#### 问题 2：在登录页停止

**可能原因**：Cookie 过期

**解决方案**：
1. 手动访问 OA 登录
2. 登录成功后刷新页面
3. 脚本会自动继续执行

#### 问题 3：会议名称格式不正确

**可能原因**：脚本中姓名模板被修改

**排查步骤**：
1. 在 Console 中执行 `generateMeetingName(new Date())`
2. 检查输出格式

**解决方案**：
- 确认 `CONFIG.meeting.nameTemplate` 正确
- 确认 `getISOWeekNumber()` 函数返回正确值

#### 问题 4：部分参会人员未找到

**可能原因**：
- 人员 UUID 已变更
- 人员在系统中已离职或调动
- 人员树未完全加载

**排查步骤**：
1. 查看 Console 中 `⚠️ 未找到人员` 警告
2. 记录失败的人员名称
3. 在 OA 系统中手动搜索确认该人员是否存在

**解决方案**：
- 更新配置中的 UUID
- 从配置中移除已离职人员
- 增加人员树等待时间

#### 问题 5：保存草稿失败

**可能原因**：
- 表单验证不通过
- 必填项未填写
- 网络超时

**排查步骤**：
1. 查看 Console 中 `❌ 保存失败` 错误
2. 检查 OA 页面是否有错误提示

**解决方案**：
- 确认所有必填项已填写
- 检查会议名称是否超长
- 检查网络连接

### 5.2 应急处理

如果测试过程中出现异常，按以下步骤处理：

1. **立即停止脚本**
   - 关闭当前标签页
   - 或刷新页面

2. **检查当前状态**
   - 手动查看 OA 页面
   - 确认当前操作进行到哪一步

3. **清理锁状态**
   - 方法 A：等待 2 分钟锁超时自动清理（推荐，无需手动操作）
   - 方法 B：在 Console 中手动执行：
   ```javascript
   GM_setValue('oa_running', false);
   GM_setValue('oa_step', 0);
   ```

4. **手动完成**
   - 根据 Console 日志，从失败的步骤手动继续

5. **记录问题**
   - 将错误日志截图保存
   - 记录失败的步骤和错误信息

6. **如果选择器失效**
   - 先安装验证脚本，查看步骤 4 输出的页面结构
   - 对比当前页面 DOM 与选择器的匹配情况
   - 更新 CONFIG.selectors 中的对应选择器
