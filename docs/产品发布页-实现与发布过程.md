## 一、目标与参考结论

参考站点：`https://zchenmaker.github.io/Epoint-video-guide/`（视频技能包 V1.03）。

按照《GitHub Pages 国内访问分析与发布方案》的实测结论，该站能在国内打开的决定性因素是**页面层完全自包含**，而不是网络通道特殊：

| 维度 | 参考站做法 | 本页是否照做 |
| --- | --- | --- |
| 页面构成 | 纯静态 HTML + 同源 CSS | ✅ 更彻底：单文件，CSS/JS 全内联 |
| 字体 | 系统字体栈，无网络字体 | ✅ 系统字体栈 |
| 图标 | 内联 SVG | ✅ 内联 SVG sprite，无图标库 |
| 统计 | 完全没有埋点 | ✅ 无任何埋点 |
| 下载 | 仓库内 zip，相对路径 | ✅ 仓库内文件，相对路径 |
| 图片来源 | 同源 `assets/` | ✅ 不用位图，界面示意图用 CSS 画 |

于是本次交付的目标不是"复制一个好看的页面"，而是：

1. 为 v1.6.1 脚本做一个能对外讲清楚的**产品发布页**；
2. 页面**零外部依赖、下载全同源**，可长期挂在 GitHub Pages；
3. 结构上能持续维护——改版本号、加一节内容不需要动架构。

## 二、交付物与文件位置

发布页放在**仓库根目录**，原因有二：GitHub Pages 只允许从 `main` 的 `/` 或 `/docs` 发布；而下载目标（`code/`、`docs/videos` 等）都在根目录，只有根目录发布才能保证所有相对路径一次到位。

```
meeting-bot/
├── index.html              # 发布页，55,657 字节，入口文件
├── .nojekyll               # 空文件，跳过 Jekyll 处理
├── code/
│   └── oa-weekly-meeting.user.js   # 下载目标：主脚本 95,668 字节
├── docs/
│   ├── 使用指南.html        # 下载目标：单页说明书 34,870 字节
│   ├── 功能演示.mp4         # 下载/播放目标：4,114,292 字节
│   ├── 脚本安装.mp4         # 下载/播放目标：923,908 字节
│   └── ……                  # 其余过程文档
└── README.md
```

`.nojekyll` 是空文件，作用是避免 Jekyll 把以下划线或点号开头的路径当特殊文件处理（本仓库当前没有此类目录，属于预防性放置）。

## 四、技术实现要点

### 4.1 单文件自包含

CSS 写在 `<style>`、JS 写在 `<script>`，不拆 `.css` / `.js`。全页仅 1 个请求即可完整渲染，与参考站"一次 GET 拿到完整 HTML"的思路一致。

### 4.2 零外部依赖的实现方式

| 环节 | 做法 | 若换成常见方案会怎样 |
| --- | --- | --- |
| 字体 | `-apple-system, "PingFang SC", "Microsoft YaHei"…` 系统栈 | 引 Google Fonts → 国内常打不开，字体回退甚至白屏 |
| 图标 | 页面顶部一段 SVG sprite，`<use href="#i-xxx">` 引用 | 引 iconfont/CDN → 图标全变方块 |
| 首屏视觉 | **纯 CSS 画 OA 配置对话框**：浏览器栏、表单行、进度条、Toast | 用截图/iframe → 多文件、多请求，且难以维护 |
| 视频 | `<video src="docs/xxx.mp4">` 同源相对路径 | 放 B 站/腾讯视频外链 → 依赖第三方域名与广告 |
| 统计 | 无 | 埋 GA → 脚本超时阻塞 `load` |

全站扫描结果：仅出现 `http://www.w3.org/2000/svg` 一处命名空间声明（浏览器不会发起请求），其余无任何外部域名。

### 4.3 为什么不用 iframe 做首屏预览

参考站用 `skill-preview.html` 同源 iframe 展示产物。本页改成了 CSS 绘制的"界面示意"：

- 少一个文件、少一次请求，部署更简单；
- 示意内容（会议名称、期次、人员）是**示例值**，页面上已标注"界面示意，字段数值为示例"，避免被误读为真实数据；
- 后续改文案只改 HTML 文本，不用维护第二套页面。

### 4.4 交互只用原生 JS（约 40 行）

| 交互 | 实现 |
| --- | --- |
| 吸顶栏阴影 | `scroll` 监听，`scrollY > 8` 时加 `.is-scrolled` |
| 移动端菜单 | `body.nav-open` 切换 + `aria-expanded` 同步 + 点击菜单项自动收起 + ESC 关闭 |
| FAQ 折叠 | 原生 `<details>/<summary>`，零 JS |
| 锚点跳转 | 原生 `scroll-behavior: smooth` |
| 视频播放 | 原生 `<video controls playsinline preload="metadata">` |

### 4.5 响应式与降级

| 断点 | 变化 |
| --- | --- |
| `≤1180px` | 首屏改单列，功能卡 3→2 列，流程 7→4 列，版本 4→2 列 |
| `≤980px` | 顶部导航收进汉堡菜单（`.mobile-nav` 固定浮层），手册/下载/视频/关于改单列 |
| `≤640px` | 标题降到 38px，功能卡单列，数据条 2 列，示意表字号缩小 |
| `print` | 隐藏导航、页脚与首屏视觉，正文按 12px 输出 |

### 4.6 可访问性处理

- 装饰性 SVG 一律 `aria-hidden="true"`；
- 汉堡按钮带 `aria-label` 与 `aria-expanded`；
- 导航容器有 `aria-label`，数据条有 `aria-label="脚本概要"`；
- 正文对比度按 `#5f6b7a` on `#ffffff` 取值，避免灰字过淡。

## 五、下载与资源策略

所有下载/播放地址均为**同源相对路径**，不使用 Release、`raw.githubusercontent.com`、`codeload` 等高风险子域：

| 页面入口 | 相对路径 | 线上实际 URL | 实测 |
| --- | --- | --- | --- |
| 下载脚本 | `code/oa-weekly-meeting.user.js` | `/meeting-bot/code/oa-weekly-meeting.user.js` | 200，95,668 B，0.58 s |
| 打开使用指南 | `docs/使用指南.html` | `/meeting-bot/docs/使用指南.html` | 200，34,870 B，0.40 s |
| 功能演示 | `docs/功能演示.mp4` | `/meeting-bot/docs/功能演示.mp4` | 200，4,114,292 B，1.88 s |
| 脚本安装 | `docs/脚本安装.mp4` | `/meeting-bot/docs/脚本安装.mp4` | 200，923,908 B，0.75 s |

## 七、过程中的四个问题（问题 → 根因 → 解决）

### 7.1 主脚本没进仓库，线上"下载脚本"404

- **问题**：三处资源返回 200，唯独 `/code/oa-weekly-meeting.user.js` 404，但本地文件确实存在。
- **根因**：`git ls-files code/` 为空——本机全局忽略文件 `/Users/lilin/.gitignore_global` 第 129 行有一条 `code` 规则，把任何名为 `code` 的目录整体忽略。首次 `git add -A` 时该目录被静默跳过，91 个文件里没有主脚本。
- **解决**：在仓库 `.gitignore` 中显式覆盖：

  ```gitignore
  # 全局忽略里有 "code" 规则，会漏掉主脚本目录；这里覆盖回来
  !code/
  !code/**
  ```

  随后 `git add code/oa-weekly-meeting.user.js` 补提交（`601b955`）并推送，Pages 自动重建，脚本恢复 200。
- **教训**：`git add -A` 之后一定要 `git status` 复核数量，或用 `git check-ignore -v <关键文件>` 抽查主产物；被忽略的目录不会报任何警告。

### 7.2 推送直接失败：`SSL_ERROR_SYSCALL in connection to ghfast.top`

- **问题**：`git push` 与 `git fetch` 均报连不上 `ghfast.top:443`。
- **根因**：全局 git 配置有两条 URL 重写：

  ```
  url.https://github.com/.insteadof=git@github.com:
  url.https://ghfast.top/https://github.com/.insteadof=https://github.com/
  ```

  第二条把任何 `https://github.com/…` 改写成镜像前缀 `https://ghfast.top/https://github.com/…`，而该镜像当前不可达（且镜像通常不承载推送鉴权）。
- **解决**：不动全局配置，只把本仓库 `origin` 写成不会被前缀匹配的形式：

  ```bash
  git remote set-url origin "https://github.com:443/andli0626/meeting-bot.git"
  ```

  `https://github.com:443/` 不匹配 `https://github.com/` 前缀，因此绕过重写；凭据仍由 macOS 钥匙串提供，无需在 URL 里写 token。

### 7.3 桌面端顶部多出一条导航

- **问题**：1440 宽度下，吸顶栏下方多出一行"核心能力 执行流程 …"，浏览器窗口变宽也不会消失。
- **根因**：`.mobile-nav` 的 `display: none` 只写在 `@media (max-width: 980px)` 内部，宽屏时该元素没有任何基础样式，按普通 `div` 参与布局。
- **解决**：把 `display: none` 提到媒体查询之外作为基础规则，媒体查询内只保留浮层样式；`body.nav-open` 时才 `display: grid`。

### 7.4 窄屏截图"内容被裁"疑似横向溢出

- **问题**：`--window-size=430` 截图时，右侧文字与按钮全部被切掉，看起来像页面超宽。
- **根因**：Chrome 无头模式在 macOS 下有最小窗口宽度，`430` 实际得到布局宽度 `485`，截图按 430 裁切——是**截图参数问题**，不是页面问题。用脚本测量 `document.documentElement.scrollWidth` 与 `clientWidth` 差值仅为滚动条宽度，确认无真实溢出。
- **解决**：改用 `520` 宽度复测；同时保留 `overflow-x: auto` 的 `.table-wrap`，让字段表在窄屏内单独横向滚动，不把整页撑宽。

## 九、维护指南

### 9.1 改文案或加内容

直接改 `index.html` → `git push` → 等 1–10 分钟（首次构建最慢）。页面为单文件，不需要重新构建资源。

### 9.2 脚本发新版时必须同步改三处

| 位置 | 内容 |
| --- | --- |
| 顶部导航 `brand small` | `V1.6.1` → 新版本号 |
| 首屏数据条 / 下载卡 | 版本号、体积（脚本字节数 /1024）、行数 |
| `#changelog` | 新增一张版本卡，旧卡保留 |

同时把新脚本覆盖到 `code/oa-weekly-meeting.user.js`，下载链接无需改动。

### 9.3 改版不生效

GitHub Pages 边缘缓存 `max-age=600`（10 分钟）。处理方法：强制刷新；或等 10 分钟；确认构建已 `built` 而不是仍在 `building`。

### 9.4 发布前自检（防境外依赖回潮）

```bash
#!/usr/bin/env bash
# 检查站点是否存在可能被墙的外部依赖
RISK='fonts\.googleapis|fonts\.gstatic|cdn\.jsdelivr|unpkg\.com|cdnjs\.cloudflare'
RISK+='|google-analytics|googletagmanager|gtag\(|hm\.baidu'
RISK+='|raw\.githubusercontent|codeload\.github|objects\.githubusercontent'
RISK+='|releases\/download|polyfill\.io|staticfile\.org|bootcdn'

fail=0
for f in $(find . -name '*.html' -o -name '*.css' -o -name '*.js'); do
  hits=$(grep -nEo "$RISK" "$f" 2>/dev/null)
  if [ -n "$hits" ]; then echo "[风险] $f"; echo "$hits" | sed 's/^/    /'; fail=1; fi
done
[ "$fail" -eq 0 ] && echo "[通过] 未发现高风险外部依赖" || { echo "[失败] 请移除后再发布"; exit 1; }
```

## 十、边界与风险

| 风险 | 说明 | 建议 |
| --- | --- | --- |
| **源码与名单公开** | 免费账号 Pages 必须 public。当前仓库里 `CONFIG.participants`（8 人真实姓名）、`participantGuids`（姓名→GUID）、`departedParticipants`（离职人员）均随脚本明文公开 | 若名单不宜外露，改为占位姓名后再发布，或把脚本托管到内网/私有仓库（私有仓库 Pages 需 Pro） |
| **政务/企业内网** | `github.io` 在多数内网直接不通，页面优化再好也打不开 | 面向客户时改用国内托管（备案）或内网地址 |
| **ISP 与时段差异** | 移动宽带、企业专线失败率更高；晚高峰 TTFB 可能从 0.6 s 涨到 3 s+ | 不作为唯一对外入口；重要分发同时给附件 |
| **Pages 禁止商用** | 免费 Pages 不能当电商/SaaS 官网使用 | 内部工具说明页合规；对外商业站另选托管 |
| **页面 10 分钟缓存** | 改版后可能仍看到旧页 | 强制刷新，或等缓存过期 |
| **单文件上限** | 打包体积受 Pages/托管限制（单文件 100 MB、站点 1 GB） | 视频已 4 MB 级，后续新增素材注意体积 |
