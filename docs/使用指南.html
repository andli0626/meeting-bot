一、功能概览

本脚本是一个运行在 Tampermonkey（篡改猴） 浏览器扩展中的用户脚本，用于自动化新点 OA 平台的周例会创建流程。传统手动填写需要 10+ 步操作，使用本脚本后可一键完成。

📝
自动填写会议信息
👥
按姓名选择参会人员
📌
自动新增议题
💾
一键保存草稿
📅
智能推算会议期次
💻
腾讯会议信息模板

自动化流程

打开 OA
→
打开会议看板
→
新增会议
→
填写信息
→
选择人员
→
新增议题
→
保存草稿

执行步骤详解

步骤名称说明
1验证页面加载与登录检测登录页、校验页面标题
2打开会议看板点击「统一会议」→「我的会议」→ 等待看板 iframe 加载
3点击新增会议在看板 iframe 中点击 #btnAdd，等待表单 iframe 加载
4填写会议信息设置会议形式（线上/线下）、日期、时间、名称
5选择参会人员通过「姓名→GUID」映射或人员弹窗解析，写入两个人员字段
6新增议题点击「新增议题」，填写名称/标签/内容，保存议题
7保存草稿点击「保存草稿」完成创建

二、前置条件

1. 支持的浏览器

  • Google Chrome（推荐）
  • Microsoft Edge（Chromium 内核）
  • Mozilla Firefox
  • Brave、Opera、Vivaldi 等 Chromium 内核浏览器

2. 必须安装的扩展

需要先安装 Tampermonkey（篡改猴） 浏览器扩展：

  • Chrome / Edge：Chrome Web Store 安装
  • Firefox：Firefox Add-ons 安装
⚠️ 注意：请使用 Tampermonkey（篡改猴），不推荐使用 GreasypFork 等替代品，部分 GM API 可能存在兼容性问题。

3. 网络与环境

  • 能够访问公司内网 oa.epoint.com.cn
  • 拥有 OA 账号并已开通「统一会议」模块权限
  • 脚本仅匹配 https://oa.epoint.com.cn/epointoa9/frame/fui/pages/themes/aide/aide* 页面

三、安装步骤

方式一：直接安装（推荐）

  1. 确保已安装 Tampermonkey 扩展
  2. 获取脚本文件 oa-weekly-meeting.user.js
  3. 点击浏览器工具栏上的 Tampermonkey 图标 → 选择 「添加新脚本」
  4. 删除编辑器中的默认模板内容
  5. 将 oa-weekly-meeting.user.js 的完整内容复制粘贴到编辑器中
  6. 按 Ctrl + S（Mac: Cmd + S）保存脚本
  7. 关闭脚本编辑器，刷新 OA 页面
  8. 看到 Tampermonkey 图标上显示数字角标，表示脚本已启用

方式二：拖放安装

  1. 将 oa-weekly-meeting.user.js 文件保存到本地
  2. 打开 Tampermonkey 管理面板 → 「工具」标签页
  3. 将脚本文件拖入浏览器窗口，Tampermonkey 会弹出安装确认
  4. 点击「安装」完成

验证安装成功

✅ 安装成功后，访问 OA 首页，点击 Tampermonkey 图标，能看到「新点OA周例会自动化」脚本处于启用状态。

更新脚本

  1. 打开 Tampermonkey 管理面板 → 「已安装脚本」
  2. 找到「新点OA周例会自动化」，点击编辑图标
  3. 全选并删除旧内容，粘贴新版本的完整代码
  4. 保存（Ctrl/Cmd + S）即完成更新

四、配置说明

脚本的核心配置集中在代码开头的 CONFIG 对象中。换团队/换环境时只需修改这些配置，无需改动流程逻辑。

4.1 会议基本配置

会议名称模板

nameTemplate: "研发4部-1组周例会-{year}年第{period}期-{mmdd}"
// 可用占位符：
//   {year}   → 会议日期的年份，如 2026
//   {period} → 会议期次，如 29
//   {mmdd}   → 会议日期的月日，如 0917
// 示例输出：研发4部-1组周例会-2026年第29期-0924

会议类型与模板

type: "0203",              // 会议类型编码（OA 后台配置）
modelGuid: "5fa25cb0-71a8-4086-b223-edd7e7e0cded",  // 会议模板 GUID
roomType: "online",        // 默认会议室类型：online / offline

4.2 会议期次推算

period: {
  base: 28,                        // 基准期次
  baseDate: "2026-09-17",          // 基准日期（该日期对应第 28 期）
}
// 推算公式：期次 = base + round((目标日期 - baseDate) / 7)
// 即基准日期之后每过一周，期次自动 +1

4.3 会议时间与腾讯会议

time: "16:00-16:30",   // 默认会议时间（HH:mm-HH:mm）

tencentMeeting: {
  topic: "周例会-研发1组",                                   // 会议主题
  time: "16:00-17:00 (GMT+08:00) 中国标准时间 - 北京",        // 时间描述
  url: "https://meeting.tencent.com/dm/RBOwS36hEUIX",       // 会议链接
  id: "969-3173-9175",                                      // 会议号
  inviter: "李林-前端",                                      // 邀请人
}

4.4 参会人员配置

// 参会人员姓名列表（配置对话框中可修改）
participants: [
  "戴科", "黄赟博", "徐灵杰",
  "曹渝澄", "周胜宇", "杨世杰", "周志银", "杨赛",
],

// 姓名 → 人员 GUID 映射（OA 隐藏域需要 GUID）
// 缺哪个人就补哪一行；缺的姓名会退化为"打开人员选择弹窗解析"
participantGuids: {
  戴科: "e92eb9b1-975a-447a-b3c4-2e61b67d443d",
  黄赟博: "2894e5ad-241b-49de-bc2e-cd106f94675d",
  徐灵杰: "8dcd74d1-3609-4396-8c03-3a0513a64b5e",
  // ... 更多人员
},

// 已离职人员（人员离职时登记到这里，会自动从名单中剔除）
departedParticipants: ["左惠"],
⚠️ 人员离职怎么办：光从 participants 里删名字可能不生效——配置对话框会把上次填的人员记在本地（GM 存储）里，下次打开对话框带出的是那份旧名单。v1.6.1 起，把离职人员写进 departedParticipants，代码名单和记住的旧名单都会自动剔除，日志会打印「已剔除离职人员: XXX」。
💡 如何获取人员 GUID：在 OA 中手动打开一次人员选择弹窗，脚本会自动从数据模型中解析出「姓名→GUID」映射（需配置对应姓名）。或者咨询 OA 管理员从后台获取。

4.5 议题配置

agenda: {
  name: "本周工作情况同步",    // 议题名称（默认值）
  label: 1,                    // 议题标签：1=ST议题, 2=AT议题, 0=其他议题
  content: "本周工作情况同步",  // 议题内容（默认与名称相同）
}

4.6 高级配置

// 是否自动执行（页面加载后自动运行）
// 建议保持 false，通过菜单手动触发，避免误操作
autoRun: false,

// 超时与重试配置
timing: {
  stepTimeout: 15000,    // 单步骤超时（毫秒）
  pollInterval: 300,     // 轮询间隔（毫秒）
  maxRetries: 3,         // 单步骤最大重试次数
  retryDelay: 2000,      // 重试间隔（毫秒）
  navigationTimeout: 30000,  // 页面导航超时（毫秒）
  lockTimeout: 120000,   // 运行锁超时（防止刷新后永久锁死）
}

五、使用指南

5.1 首次使用

  1. 登录新点 OA 平台，进入 OA 首页
  2. 点击浏览器工具栏上的 Tampermonkey 图标
  3. 在菜单中选择 「立即执行创建周例会」
  4. 弹出配置对话框，核对以下信息：
    • 会议日期：默认为下一个周四
    • 会议期次：根据基准日期自动推算
    • 会议名称：按模板自动生成
    • 会议形式：线上/线下
    • 腾讯会议信息：线上会议时显示
    • 议题名称：默认「本周工作情况同步」
    • 参会人员：多人用顿号（、）或逗号分隔
  5. 确认无误后点击 「确认执行」
  6. 脚本自动执行全部步骤，右下角显示执行进度与结果面板
  7. 执行成功后，到「我的会议 → 会议列表（草稿）」核对并提交
💡 配置记忆：首次执行后，脚本会自动保存你的配置（议题名称、参会人员、会议形式、腾讯会议信息、会议时间），下次打开配置对话框会自动带出。

5.2 日常使用

  1. 打开 OA 首页
  2. Tampermonkey 菜单 → 「立即执行创建周例会」
  3. 配置对话框中通常只需确认/微调日期、议题名称
  4. 点击「确认执行」，等待完成

5.3 配置对话框说明

字段说明是否必填
会议日期选择会议日期，默认下一个周四是
会议期次自动推算，可手动调整是
开始/结束时间格式 HH:mm，如 16:00是
会议名称按模板自动生成，可手动修改是
会议形式线上会议 / 线下会议是
腾讯会议信息仅线上会议时显示线上时建议填写
议题名称如「本周工作情况同步」是
参会人员多人用、或逗号分隔是

5.4 中断与取消

  • 配置对话框打开时，点击 「取消」 或按 ESC 键可取消执行
  • 脚本执行过程中如需中断，可刷新页面，运行锁会在 2 分钟后自动释放
  • 如果脚本异常中断导致一直提示「执行中」，使用菜单「清除运行锁」重置

七、常见问题

Q1：脚本没有生效 / 菜单看不到？
  1. 确认 Tampermonkey 扩展已安装并启用
  2. 确认脚本已启用（Tampermonkey 面板中开关为蓝色）
  3. 确认当前页面 URL 为 OA 首页（匹配 oa.epoint.com.cn/epointoa9/frame/fui/pages/themes/aide/aide*）
  4. 刷新页面后再次尝试
  5. 按 F12 打开开发者工具 → Console，查看是否有脚本报错
Q2：执行失败，提示「会议看板 iframe 加载超时」？
  • 检查网络连接是否正常，OA 页面是否完全加载
  • 确认账号有「统一会议」模块权限
  • 手动点击「统一会议」→「我的会议」，确认能正常打开看板
  • 尝试增大 timing.stepTimeout 配置值
Q3：人员写入失败或为空？
  • 确认 participantGuids 配置中补全了所有参会人员的 GUID
  • 使用「诊断会议表单」菜单查看实际的人员字段名
  • 如果姓名不匹配（如 OA 中是「张三」配置中是「张三丰」），修正配置中的姓名
  • 脚本会优先使用配置的 GUID，缺失时才尝试从人员弹窗解析
Q4：议题名称被清空 / 写入失败？

这是已知问题（议题编辑页异步数据回填会覆盖已写入字段）。v1.6.0 已修复：

  • 脚本采用「稳定写入」策略：写入后回读校验，被覆盖时自动重写
  • 保存前再次检查所有字段，发现被覆盖则重新写入

如果仍有问题，请查看执行日志并反馈。

Q5：脚本一直提示「脚本正在执行中」？

这通常是因为脚本异常中断（如刷新页面、关闭标签页）导致运行锁未释放。

  • 方法一：等待 2 分钟，锁会自动超时释放
  • 方法二：Tampermonkey 菜单 → 「清除运行锁（卡在执行中时用）」
Q6：会议日期/时间显示为创建时间？

v1.6.0 已修复此问题。脚本现在会显式写入配置的会议日期与起止时间。

如果使用旧版本，请更新脚本。

Q7：如何切换到另一个团队/部门？

修改 CONFIG 中的以下配置：

  • nameTemplate：会议名称中的部门/组名
  • participants：参会人员姓名列表
  • participantGuids：对应的人员 GUID
  • tencentMeeting：腾讯会议信息
  • period.base / baseDate：期次基准
Q8：线上会议时「新增议题」无反应？

这是因为表单必填项校验未通过。脚本已处理以下情况：

  • 自动将会议形式切换为「线上会议室(01)」
  • 自动填写「其他会议室」字段（腾讯会议信息）
  • 触发会议形式联动逻辑

如果仍失败，请查看执行日志中「步骤 6」的输出，通常是其他必填项未填写。

Q9：如何查看详细的执行日志？
  • 页面内面板：Tampermonkey 菜单 → 「查看执行日志」（可滚动、可复制）
  • 浏览器控制台：F12 → Console，过滤 [OA-Weekly]
  • 日志前缀：[OA-Weekly]，级别：DEBUG / INFO / WARN / ERROR
Q10：支持线下会议吗？

支持。在配置对话框中选择「线下会议」即可。

⚠️ 注意：线下会议时，「公司会议室」字段需要人工选择，脚本不会自动填写。请在草稿中手动补充会议室信息。

九、技术细节

9.1 技术栈

  • 原生 JavaScript（ES6+），无需任何外部依赖
  • Tampermonkey GM API：GM_setValue / GM_getValue / GM_info / GM_addStyle / GM_registerMenuCommand
  • 适配 OA 平台的 mini-ui 控件库

9.2 核心机制

机制说明
轮询等待所有 iframe/元素等待均采用轮询机制，避免错过异步加载内容
重试机制每个步骤支持最多 3 次重试，应对网络波动
运行锁防止重复触发，超时 2 分钟自动释放
稳定写入写入字段后回读校验，被页面异步回填时自动重写
多级 iframe 遍历递归收集所有可访问文档，支持跨 iframe 查找元素
配置持久化使用 GM_setValue 保存用户配置，跨会话记忆

9.3 安全说明

  • 脚本仅在匹配的 OA 页面运行，不会访问其他网站
  • 所有数据保存在浏览器本地（GM 存储），不上传到任何服务器
  • 人员 GUID 由用户自行配置，脚本不主动获取或传输
  • 执行结果仅为「草稿」，需人工核对后正式提交
