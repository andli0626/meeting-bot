Features

六大核心能力

不是把表单填满的宏，而是把「点开、勾选、回读、保存」这一整套动作做成可复用的流程。

一键创建

从打开会议看板到保存草稿全自动，共 7 步。中间不用你点任何按钮，进度在右上角实时走。

  • 菜单「立即执行创建周例会」触发
  • 先弹配置对话框，核对后再动手
  • 执行中可随时查看状态与日志

智能推算

自动算出下一个周四与会议期次，按模板拼出会议名称；改日期，名称与期次跟着一起变。

  • 默认下一个周四，可手改
  • 期次按内置基准每期 +1
  • 名称格式 部门-组周例会-年第N期-MMDD

人员选择

按姓名去 OA 人员弹窗勾选，并把结果同步写回「参会人员」与「列席人员」两行，保证两边名单一致。

  • 姓名 → GUID 映射，缺的可补
  • 人员字段写入后回读校验
  • 离职人员自动从名单剔除（v1.6.1）

配置记忆

会议名称、形式、议题、人员等配置存在浏览器本地，下次打开对话框自动带出，不用每周重填。

  • 存于篡改猴 GM 存储，不上传
  • 菜单「重置本地配置」可恢复默认
  • 记住的旧名单也会剔除离职人员

执行反馈

右上角进度提示 + 可滚动日志面板，成功弹结果面板并倒计时关闭，失败则保留现场方便排障。

  • 日志前缀统一 [OA-Weekly]
  • 最近 20 条日志在页面内直接看
  • 失败面板不自动关闭

团队可复用

换团队、换模板只改脚本顶部 CONFIG，流程与选择器不动；同一套 OA 的部门可直接复制使用。

  • 会议名称模板、模板 GUID、期次基准
  • 人员名单与姓名 GUID 映射
  • 腾讯会议信息模板可整段替换

Workflow

七步执行流程

每周重复的那一段，脚本替你做。任何一步出问题都会停在原地并写进日志，不会留下半成品草稿。

01

验证页面

确认在 OA 首页、已登录，否则提示并退出。

02

打开会议看板

进入统一会议 / 我的会议，定位「新增会议」入口。

03

新增会议

打开会议表单 iframe，等待模板加载完成。

04

填写会议信息

写入名称、日期、起止时间、形式与腾讯会议信息。

05

选择人员

按姓名勾选参会 / 列席，并回写两行隐藏字段。

06

新增议题

选标签、填议题名称与内容，被异步覆盖就重写。

07

保存草稿

保存并回读草稿列表，弹出结果面板与最近日志。

脚本到「保存草稿」为止：不提交、不通知参会人、不改任何他人数据。 草稿确认无误后，仍由你在 OA 里手动提交——流程的最后一公里，留给人。

Manual

使用手册

装一次，之后每周点两下：点菜单、点确认。剩下的核对，只看四处。

安装（3 步）

  1. 1

    浏览器安装 篡改猴（Tampermonkey） 扩展，Chrome / Edge 均可。

  2. 2

    把 oa-weekly-meeting.user.js 拖进浏览器窗口，弹出安装页后点「安装」；或「添加新脚本…」粘贴全文保存。

  3. 3

    确认脚本开关为 已启用。脚本只在 OA 首页生效，其它页面不加载。

首次执行（4 步）

  1. 1

    登录 OA，停留在 OA 首页，标签页保持打开。

  2. 2

    点篡改猴图标 → 菜单「立即执行创建周例会」。

  3. 3

    在「周例会配置确认」里核对字段，点「确认执行」。

  4. 4

    右上角出现进度提示，跑完弹出成功 / 失败面板。

结果核对（4 处）

  1. 1

    到「我的会议 → 会议列表（草稿）」，核对名称、日期、形式、会议室。

  2. 2

    核对 参会人员 与 列席人员 是否就是配置的那批人。

  3. 3

    核对议题名称与议题内容，标签是否选对。

  4. 4

    线上会议时，确认议题内容里带上了腾讯会议信息。

配置字段默认值说明
会议日期下一个周四改动后会议名称与期次自动跟着变，起止时间一起写入。
会议期次按基准推算以某天为第 N 期，之后每周 +1；可手改。
会议名称部门-组周例会-年份第N期-MMDD按 CONFIG.meeting.nameTemplate 生成，可手改。
会议形式线上会议选线下时不写入腾讯会议信息；新增议题前必须已选会议室。
腾讯会议信息主题 / 时间 / 链接 / 会议号 / 邀请人线上会议时追加到「议题内容」。
议题名称本周工作情况同步标签 1=ST议题、2=AT议题、0=其他。
参会人员姓名列表多人用「、」或逗号分隔，按姓名去 participantGuids 取 GUID。
菜单命令用途
立即执行创建周例会打开配置对话框并执行完整流程。
查看执行状态查看是否在执行、执行到第几步。
查看执行日志弹出最近 20 条日志，页面内可滚动（排障用）。
清除运行锁脚本异常中断后一直提示「执行中」时清锁；也有 2 分钟超时自动解锁。
重置本地配置清掉记住的配置，回到脚本内置默认值。
诊断会议表单打开表单转储字段后关闭，不产生草稿。
提示「脚本正在执行中」，但我并没有在跑？
菜单点「清除运行锁」。脚本也有 2 分钟超时自动解锁；清锁后再执行一次即可。
某一步报「未找到元素 / 超时」？
多半是 OA 页面结构或会议模板变了。先用「查看执行日志」定位失败步骤与诊断信息，再对照脚本里 CONFIG.selectors 调整选择器或模板配置。
人员没写上，或只写上了一部分？
脚本按「姓名 → GUID」写入，日志会打印 已写入人员字段 seatnames（N 人） 与回读值。 提示「取不到 GUID」就补齐 CONFIG.participantGuids；GUID 可在「新增会议」页手动选一次人员后，从 #seatnames$value 隐藏值读取。 姓名要与 OA 通讯录完全一致（含异体字）。
议题名称在草稿里是空的？
议题编辑页会异步回填表单，脚本已做「写入 → 回读 → 被覆盖就重写」，日志会打印 议题字段回填。若仍为空，请把日志发出来。
换人、换会议室、换模板怎么办？
只有同一套 OA（域名、版本一致）才能直接复用选择器，其余改动集中在脚本顶部 CONFIG： 会议名称模板、会议类型、模板 GUID、期次基准、腾讯会议模板、人员名单与 GUID 映射。 改完保存即可，流程代码不用动。
人员离职后，为什么删了名字还照样写进会议？
因为对话框优先带出浏览器里记住的旧名单，代码里的新名单读不到。v1.6.1 起把离职人员登记到 CONFIG.departedParticipants， 代码名单与记住的旧名单都会被自动剔除，日志会打印「参会人员名单中已剔除离职人员: XXX」。

为什么是油猴脚本，而不是一个系统

周例会创建这件事，难点不在业务逻辑，而在 OA 页面里那一串重复动作：找入口、等 iframe、填名称、勾人、加议题、保存。 做一个后台系统要申请权限、对接接口、走上线流程；而脚本直接运行在你已经登录的页面上，不碰接口、不拿账号、不留服务端。

代价也很明确：它依赖 OA 的页面结构，模板一改就可能失效——所以脚本把选择器、模板 GUID、人员映射全部收进 CONFIG， 并且把每一步的失败都写进日志，让你能在两分钟内判断是「配置变了」还是「被限权了」。

这一页本身也照同一套原则做：单文件、零外部依赖、下载走同源相对路径。没有网络字体、没有第三方 CDN、没有统计脚本， 断网时除了视频，其余内容照常可读。

能做什么新增会议、填信息、选人员、加议题、保存草稿。
不做什么不发会议通知、不提交、不改别人创建的数据、不读取会议内容。
依赖什么篡改猴扩展 + 同一套新点 OA（域名与版本一致）。
